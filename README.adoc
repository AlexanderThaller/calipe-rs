= calipe-rs

`calipers` is a lightweight system metrics agent for FreeBSD that exposes a Prometheus endpoint. It
replaces a Telegraf setup (see `resources/telegraf.conf`) and reads everything in-process through
sysctl and ioctl: no `zpool`, `pfctl`, `smartctl` or `chronyc` processes. Design notes, metric
definitions and verification details are in link:dev.adoc[`dev.adoc`].

== Deploy

On the FreeBSD host, as root, from a checkout of this repository:

[source,sh]
----
resources/deploy.sh          # build (cargo --profile deploy), install, restart
sysrc calipers_enable=YES    # first time only
service calipers start       # first time only
----

`deploy.sh` installs `/usr/local/bin/calipers` (atomically), `/usr/local/etc/rc.d/calipers`, and the
example config to `/usr/local/etc/calipers.toml` if none exists yet. Before restarting, the new binary
checks the existing config and that every input can start (`calipers --check-config`), so a failing
deploy leaves the running version untouched. `--binary PATH` installs a prebuilt binary,
`--no-restart` skips the restart.

== Nix

`nix build` builds `calipers` (`deploy` profile, stable Rust from rust-overlay); `nix develop` gives
a shell with the toolchain, rust-analyzer and `protoc`. On NixOS, import the module from the flake:

[source,nix]
----
{
  inputs.calipe-rs.url = "git+ssh://git@git.thaller.ws:4223/shared/calipe-rs.git";

  outputs = { nixpkgs, calipe-rs, ... }: {
    nixosConfigurations.host = nixpkgs.lib.nixosSystem {
      modules = [
        calipe-rs.nixosModules.default
        {
          services.calipers = {
            enable = true;
            openFirewall = true;
            settings = {
              exporter.listen = "0.0.0.0:9273";
              inputs.internal = { };
              inputs.http_response = [ { urls = [ "https://example.org/" ]; } ];
            };
          };
        }
      ];
    };
  };
}
----

`settings` is rendered to TOML (or set `configFile`). The unit runs as a dynamic user with systemd
hardening, checks the config before starting, and `systemctl reload calipers` sends SIGHUP. On Linux
only the `internal`, `http_response`, `dns_query` and `chrony` inputs exist; the others are
FreeBSD-only and fail the config check. `nix flake check` runs the tests and a NixOS VM test of the
module.

== Service

`/etc/rc.conf` variables:

[cols="1,2,3"]
|===
|Variable |Default |Meaning

|`calipers_enable` |`NO` |Start at boot.
|`calipers_config` |`/usr/local/etc/calipers.toml` |Configuration file.
|`calipers_flags` |(empty) |Extra command line flags.
|`calipers_user` |`root` |User to run as; pf, smart and procstat of other users need root.
|`calipers_env` |`RUST_LOG=info` |Environment, e.g. `RUST_LOG=calipers=debug`.
|`calipers_syslog_tag` |`calipers` |Syslog tag.
|===

calipers runs under daemon(8), which restarts it 5 seconds after an exit and sends its log to syslog
(`/var/log/messages`). `service calipers checkconfig` validates the configuration.

`service calipers reload` validates the configuration, then sends SIGHUP to calipers, which rereads
it without restarting. Inputs whose `[inputs.*]` sections are unchanged keep running with their
state; changed inputs restart, removed ones stop (their series expire after three times the longest interval). If the
file doesn't parse or an input can't start, nothing changes and the error is logged. A changed
`agent.interval` restarts every input. `exporter.listen`, `global_tags`, `agent.hostname` and
`agent.omit_hostname` only take effect after `service calipers restart`; a reload logs a warning.

== Command line

[source]
----
calipers [--config PATH] [--check-config] [--once]
----

* `--check-config`: parse the config and set up every input, then exit.
* `--once`: collect once, print the metrics to stdout and exit (handy for debugging).

== Grafana

`resources/grafana/calipers.json` is an overview dashboard for any number of hosts. Import it in
Grafana (Dashboards, New, Import) or provision it from a file; it asks for a Prometheus data source.

* The `Job`, `Realm` and `Host` variables select hosts (multi-select, default all). Click a host name
  in a table to show only that host.
* Top: totals across the selected hosts (CPU, memory, network, fullest filesystem and pool, open
  problems, collector errors), then one table row per host.
* CPU, memory, storage and network as time series per host; Health lists everything unhealthy right
  now (ZFS, SMART, HTTP and DNS probes, chrony) and SMART per drive.
* Collapsed rows: probe tables and latencies, monitored processes, and calipers' own collector
  timings.

`resources/grafana/calipers-probes.json` covers the HTTP and DNS probes: success ratios, latency
quantiles over the selected range, failures by result, and per URL (`URL` variable) and per DNS
server (`DNS server` variable) a heatmap of the native latency histogram next to p50/p90/p99/avg.
The heatmaps need Prometheus native histograms end to end (see `dev.adoc`).

The JSON is generated: edit `resources/grafana/generate.py` (overview), `generate_probes.py`
(probes) or the shared `dashlib.py`, and run
`python3 resources/grafana/generate.py > resources/grafana/calipers.json` and
`python3 resources/grafana/generate_probes.py > resources/grafana/calipers-probes.json`.

== Development

* `cargo test`, `cargo clippy --all-targets` (Linux) and
  `cargo clippy --all-targets --target x86_64-unknown-freebsd`.
* `resources/firecracker/scripts/cross-build.sh build --release` cross-compiles for FreeBSD
  (clang + lld, FreeBSD base as sysroot; `FREEBSD_VERSION=14.5` for 14.x).
* Test VMs: `resources/firecracker/` (FreeBSD 15.1, UFS) and `resources/qemu/vm.sh` (FreeBSD 15.1 with
  ZFS root and emulated SATA/NVMe drives for SMART).
