= calipe-rs: Development Plan
:toc: left
:toclevels: 2
:icons: font

A Rust replacement for the Telegraf setup in `resources/telegraf.conf`, running on a FreeBSD host
and exposing a Prometheus endpoint. Priorities: *correctness* first, then *low resource usage*.

NOTE: This document is for review before implementation starts. Items marked *[decide]* need your input;
everything else is my proposed default.

== Goals and non-goals

.Goals
* Cover every input in `resources/telegraf.conf` on FreeBSD (amd64; tested on 15.1, 13.x/14.x expected to work).
* Pull-only: expose metrics over HTTP via https://github.com/metrics-rs/metrics[metrics-rs] +
  `metrics-exporter-prometheus`. No push outputs.
* Use proper Prometheus semantics where Telegraf doesn't (real counters, base units, label names that
  follow conventions), even if this breaks existing Telegraf dashboards.
* Single static binary, one small config file, rc.d script for FreeBSD.

.Non-goals
* Config compatibility with Telegraf. We use our own config format (close to Telegraf's).
* Plugins beyond what the config uses. Adding a module later should be easy.
* Linux support for the system collectors. Portable modules (DNS, HTTP, chrony, exec, smart, pf/zpool
  parsing) work on Linux anyway, which helps local testing.

== Architecture

----
main
 ├─ config (TOML, serde, deny_unknown_fields)
 ├─ exporter (metrics-exporter-prometheus, HTTP listener, global labels)
 ├─ scheduler (tokio current_thread runtime, one task per collector, own interval)
 └─ collectors/
     ├─ cpu, mem, swap, system, kernel, disk, diskio, net, netstat, zfs     (sysctl/libc, sync)
     ├─ processes + procstat                                                (one shared process-table read)
     ├─ chrony, dns_query, http_response                                    (async network)
     ├─ smart, pf, zpool part of zfs, exec                                  (async subprocess)
     └─ internal                                                            (self-monitoring)
----

=== Decisions

[cols="1,3,2"]
|===
|Topic |Decision |Rationale

|Runtime
|`tokio` with a *current_thread* runtime. Sysctl collectors run inline (they take microseconds to
milliseconds); network and subprocess collectors are async.
|One thread instead of a pool. A scrape may wait a few ms while a sysctl collector runs, which is fine.

|Collection model
|Interval-based: each collector updates metrics-rs handles every `interval` (default 10s, overridable
per input). This is how Telegraf works, and how metrics-rs is built.
|Alternative: collect on scrape (node_exporter style). That doesn't fit metrics-rs's push-into-registry
model.

|Stale series
|`idle_timeout` on the exporter = 3 × the longest collector interval. Series that stop being updated
(for example a process that exits, a disk that's unplugged) disappear.
|Telegraf's prometheus_client output does the same thing with `expiration_interval`.

|Counters
|Monotonic kernel counters are exported as Prometheus *counters* (`counter!().absolute(v)`, `_total`
suffix). Telegraf exports everything as gauges/untyped.
|Makes `rate()` correct and lets Prometheus handle counter resets. metrics-rs counters are `u64`, so
cumulative values with fractional seconds (CPU time, I/O time) are exported as gauges that keep the
`_total` name. PromQL's `rate()` works the same on them; only the `# TYPE` line differs.
metrics-rs implements `Counter::absolute` as `fetch_max`, so an exported counter can't decrease.
Per-object counters that reset while calipers runs (recreated interfaces, re-attached disks,
re-imported pools, reused PIDs) go through `counter::Monotonic`, which carries the previous total
forward as an offset so `rate()` stays correct across the reset.

|CPU usage
|Export raw `cpu_seconds_total{cpu,mode}` (ticks / `kern.clockrate` stathz) instead of Telegraf's
precomputed `usage_*` percentages.
|Precomputed percentages throw away data between scrapes. `rate()` gives exact averages over any window.

|Latencies
|Histograms (`histogram!`) with one global set of bucket bounds, 10 µs to 10 s
(`LATENCY_BUCKETS` in `main.rs`), for probe latencies and `calipers_collector_duration_seconds`.
Setting buckets makes metrics-exporter-prometheus emit real histograms instead of summaries.
|Histograms aggregate across series and hosts (`histogram_quantile`, `rate(_sum)/rate(_count)`);
summary quantiles don't.

|Units
|Base units in names: `_bytes`, `_seconds`, `_celsius`. No milliseconds, no KiB, no pages.
|Prometheus conventions.

|Global labels
|`[global_tags]` + `host` (from `gethostname` unless `omit_hostname`) become exporter-wide global
labels.
|Same as Telegraf.

|FreeBSD data sources
|Direct `sysctl(3)`/libc calls. MIBs are resolved once at startup (`sysctlnametomib`) and read via
`sysctl(mib)` after that. A small sysctl walker is used for dynamic subtrees (ZFS kstats).
|No `fork`/`exec` for anything the kernel exposes directly. Much cheaper than gopsutil's mix of sysctl
and command parsing.

|Subprocesses
|Only where there's no stable kernel ABI: `smartctl` (JSON output, `-j`), `pfctl -s info`, `zpool list -Hp`,
and `exec`.
|`pf`'s `DIOCGETSTATUS` struct changes size between releases, and libzfs has no stable ABI. Parsing text
that's meant for scripts is the more robust option.

|HTTP client
|`reqwest` (rustls + ring, webpki roots, no redirects followed, matching Telegraf's default).
|ring avoids aws-lc-rs's C/cmake build, which makes cross-compiling for FreeBSD easier. *[decide]*: webpki
bundled roots vs. the system trust store (`/usr/local/share/certs`). Proposed: webpki roots.

|DNS client
|A small hand-written DNS query over UDP (query + header/rcode parsing).
|We only need rcode and timing, so a full DNS library (hickory) isn't worth the dependency.

|chrony
|Native chrony command protocol (v6, `REQ_TRACKING`) over UDP to `127.0.0.1:323`. No `chronyc`.
|Recent Telegraf versions do the same. No process spawn every 10 seconds.

|Regex
|`regex` crate for procstat `exe`/`pattern`.
|Same semantics as Telegraf's pgrep-like matching.

|Errors
|A collector failure is logged (rate-limited) and counted in
`calipers_collector_errors_total{collector}`. It never takes down the agent. Startup config errors are
fatal.
|

|Logging
|`tracing` + `tracing-subscriber`, logs to stderr (works with daemon(8)/syslog in rc.d).
|
|===

=== Crates (proposed)

`metrics`, `metrics-exporter-prometheus` (default features off, `http-listener` only), `tokio`,
`serde` + `toml`, `humantime-serde`, `libc`, `regex`, `reqwest`, `serde_json` (smartctl),

== FreeBSD ABI concerns

These are the parts that are most likely to be wrong, so each one gets verified on a real FreeBSD VM
(see <<testing>>).

* *libc crate FreeBSD version.* Checked: `libc` 0.2.190 defaults to the FreeBSD 12 ABI (64-bit
  `ino_t`/`dev_t`, current `statfs` and `kinfo_proc`), which matches 13, 14 and 15. No pinning needed.
* *`struct devstat`* (diskio, read via `kern.devstat.all`). It isn't in the `libc` crate, so we parse it
  by offset (288 bytes on LP64) and check `kern.devstat.version == 6` at startup. Records with
  `sequence0 != sequence1` were torn by a concurrent update and are skipped; `EBUSY` (device list
  changed mid-read) is retried.
* *`struct xswdev`* (swap, `vm.swap_info.N`). Version 2, 64-bit `dev_t`.
* *`kinfo_proc`*: we only use the stable fields (pid, comm, stat, uid, rssize, size, numthreads, start,
  rusage).
* *Truncated process names*: `ki_comm` is limited to 19 characters (`http_responsetime_exporter` gets cut
  off). When `comm` is at the limit, we take the basename of `argv[0]` from `kern.proc.args.<pid>` and
  use it if it starts with `comm`.
* *`getfsstat`* instead of `getmntinfo`, because `getmntinfo` uses a static buffer and isn't thread-safe.

== Modules

Order is the implementation order. Each module = one file under `src/collectors/`, unit tests for every
parser/decoder, verified on the FreeBSD VM.

[cols="1,2,3"]
|===
|Module |Source on FreeBSD |Metrics (labels) — changes from Telegraf

|cpu
|`kern.cp_times`, `kern.cp_time`, `kern.clockrate`; optional `dev.cpu.N.temperature`, `dev.cpu.N.freq`
|`cpu_seconds_total{cpu,mode}` per CPU and `cpu_all_seconds_total{mode}` summed over all CPUs (a
separate metric, so `sum(rate(cpu_seconds_total[5m]))` doesn't double count); modes are user, nice,
system, interrupt, idle. Opt-in `cpu_temperature_celsius{cpu}`,
`cpu_frequency_hertz{cpu}`. *[decide]*: is `/root/src/priv/scripts/freebsd_cpu` (exec) reporting
temperature/frequency? If so, the native option replaces it.

|mem
|`vm.stats.vm.v_*_count`, `hw.pagesize`, `hw.physmem`, `vfs.bufspace`, `kstat.zfs.misc.arcstats.{size,c_min}`
|See <<memory-model>>. `mem_bytes{state}` (active, inactive, laundry, wired, free, other; sums to
`mem_managed_bytes`), `mem_physical_bytes`, `mem_available_bytes`, wired breakdown
`mem_{buffer,user_wired,zfs_arc}_bytes`, `mem_zfs_arc_min_bytes`, pressure signals
`mem_free_target_bytes`, `mem_pagedaemon_{wakeups,scanned_pages}_total`. No `used`/`used_percent`:
derive them in PromQL.

|swap
|`vm.swap_info.N` (`struct xswdev` v2), `vm.stats.vm.v_swappgs{in,out}`
|`swap_{total,used}_bytes{device}` (free = total - used in PromQL), `swap_{in,out}_bytes_total` as
real counters. Values match `swapinfo -k` and `sysctl` exactly.

|system
|getloadavg(3), `kern.boottime`, `hw.ncpu`, utmpx (getutxent(3))
|`system_load{1,5,15}`, `system_boot_time_seconds` (instead of uptime; uptime = `time() - boot_time`),
`system_cpus`, `system_users` (sessions), `system_unique_users`

|kernel
|`vm.stats.sys.v_{swtch,intr,soft,syscall,trap}`, `vm.stats.vm.v_{forks,vforks,rforks,kthreads}`
|`kernel_context_switches_total`, `kernel_interrupts_total{type=hard\|soft}`, `kernel_syscalls_total`,
`kernel_traps_total`, `kernel_forks_total{type=fork\|vfork\|rfork\|kthread}`, all real counters.
Telegraf's `inputs.kernel` is *Linux-only*, so on FreeBSD this is new data.

|disk
|`getfsstat(MNT_NOWAIT)` to list mounts, then a fresh `statfs` per mount on the blocking pool
|`disk_{total,free,avail}_bytes`, `disk_inodes_{total,free}{path,device,fstype,mode}`. Used =
total - free in PromQL. Pseudo filesystems (devfs, fdescfs, procfs, linprocfs, linsysfs, autofs,
mqueuefs, and anything with zero blocks) are always skipped; `ignore_fs` and `mount_points` as in
Telegraf. All ZFS dataset mounts are reported (Telegraf's behavior). Matches `df -k -i` on UFS and ZFS.

|diskio
|`kern.devstat.all` (one sysctl for all disks; `struct devstat` v6, identical on 14.5 and 15.1, parsed
by offset and version-checked)
|`diskio_operations_total{device,type}`, `diskio_bytes_total{device,type}`,
`diskio_time_seconds_total{device,type}` (type = read, write, free (TRIM), other (flush)),
`diskio_busy_seconds_total{device}` (rate = iostat `%b`, includes the in-flight interval),
`diskio_in_progress{device}`. pass(4) devices and torn records are skipped; optional `devices`
filter. Matches `iostat -I -x`.

|net
|One `NET_RT_IFLISTL` routing sysctl for all interfaces (`if_msghdrl` + `if_data`, identical on 14.5 and
15.1; header and data offsets come from the message itself)
|`net_{received,sent}_bytes_total`, `net_{received,sent}_packets_total`,
`net_{received,sent}_multicast_packets_total`, `net_{receive,send}_errors_total`,
`net_{receive,send}_drops_total`, `net_collisions_total` (real counters), `net_link_up`,
`net_speed_bits_per_second{interface}`. Default: all interfaces that are up and not loopback (like
Telegraf); `interfaces` takes globs. Matches `netstat -ibdn`.

|netstat
|`net.inet.tcp.states` (kernel-maintained `uint64[11]` per-state counts, IPv4 + IPv6) and the 64-byte
`xinpgen` header of `net.inet.udp.pcblist` (read alone; the kernel stops with `ENOMEM` before copying
any socket)
|`netstat_tcp_connections{state}` (netstat(1) names: LISTEN, ESTABLISHED, TIME_WAIT, ...; all 11 states
always present), `netstat_udp_sockets`. No socket list walk, unlike Telegraf. Matches `netstat -an` and
`sockstat`.

|processes + procstat
|One `kern.proc.proc` read per interval, shared by both; `kern.proc.args.<pid>` only for `pattern`
queries and truncated names; `kern.proc.filedesc.<pid>` only for matched processes
|`processes{state}` (ps(1) letters: running, sleeping, idle (asleep > 20 s), blocked (D), stopped,
zombie, waiting, lock), `processes_threads`. procstat: `procstat_lookup_pids{query}`,
`procstat_cpu_seconds_total{mode}`, `procstat_memory_{rss,virtual}_bytes`, `procstat_threads`,
`procstat_open_fds` (Telegraf has none on FreeBSD), `procstat_start_time_seconds`,
`procstat_context_switches_total{type}`, `procstat_block_io_total{op}`,
`procstat_page_faults_total{type}`. Labels `query` (e.g. `exe=nginx`), `process_name`, `user`, and
`pid` with `tag_with = ["pid"]`; otherwise summed per (query, name, user) with counters accumulated
from per-process increments so exits don't make totals drop. `exe`/`pattern` are regexes like
pgrep(1)/`pgrep -f`; names cut at 19 characters are restored from argv. Exact duplicate queries are
ignored with a warning. procstat shares the `processes` interval.

|zfs
|`kstat.zfs.misc.{arcstats,zfetchstats}` (sysctl walk at startup, reads by MIB), `/dev/zfs` ioctls
(`POOL_CONFIGS`, `POOL_GET_PROPS`, `POOL_STATS`) decoded in-process, `kstat.zfs.<pool>.misc.state`.
*No `zpool` process.* See <<zfs-native>>.
|`zfs_<kstat>_<field>` (event counts as counters with `_total`, everything else gauges),
`zfs_pool_{size,allocated,free,freeing}_bytes`, `zfs_pool_fragmentation_ratio`, `zfs_pool_dedup_ratio`,
`zfs_pool_health{pool,state}` (0/1 for every state), `zfs_pool_{ops,bytes}_total{pool,type}`,
`zfs_vdev_state{pool,vdev,state}`, `zfs_vdev_errors{pool,vdev,type=read\|write\|checksum}` (gauge: current count, reset by `zpool clear`),
last scrub/resilver: `zfs_pool_scan_info{pool,function,state}`,
`zfs_pool_scan_{start,end}_time_seconds`, `zfs_pool_scan_{to_examine,issued}_bytes`,
`zfs_pool_scan_errors`. Config: `kstats`, `pools`, `vdevs` (replaces Telegraf's `poolMetrics`).

|chrony
|chrony command protocol v6 (`REQ_TRACKING`, request padded to the reply length) over UDP to
`127.0.0.1:323`; no `chronyc`
|`chrony_system_time_correction_seconds` (positive = clock slow), `chrony_{last,rms}_offset_seconds`,
`chrony_frequency_ppm` (negative = slow, as in `chronyc -c`), `chrony_residual_frequency_ppm`,
`chrony_skew_ppm`, `chrony_root_{delay,dispersion}_seconds`, `chrony_update_interval_seconds`,
`chrony_reference_time_seconds`, `chrony_stratum`, `chrony_synchronized`, and
`chrony_tracking_info{reference_id,reference_ip,leap_status}` instead of Telegraf's tags on every
field. Matches `chronyc -c tracking`; config `server`, `timeout`.

|dns_query
|Hand-written UDP DNS client (RFC 1035 query with RD; reply accepted only if ID, QR bit and echoed
question match); all probes of all blocks run concurrently in one collector
|`dns_query_duration_seconds{server,domain,record_type}` (histogram, replies only),
`dns_query_total{...,result,rcode}` (result = success, rcode, timeout, error),
`dns_query_success` (last probe got NOERROR), `dns_query_answers`. Config as in Telegraf: `servers`,
`domains`, `record_type`, `port`, `timeout` (default 2s).

|http_response
|reqwest
|`http_response_duration_seconds`, `http_response_status_code`, `http_response_content_length_bytes`,
`http_response_success{url,method}`, `result` label (success, timeout, connection_failed, ...)

|smart
|`smartctl --scan -j`, then `smartctl -j -a -n standby <dev>` for each device
|`smart_device_healthy`, `smart_temperature_celsius`, `smart_power_on_seconds`,
`smart_power_cycles_total`, `smart_attribute_{value,worst,threshold,raw}{id,name}`, NVMe health-log fields.
Drives in standby are skipped (`nocheck = standby`). Default interval *60s*, not 10s: running smartctl
every 10s is wasteful, and SMART data changes slowly. *[decide]*: `path_nvme` (nvmecontrol) gets dropped,
since smartctl JSON already covers NVMe.

|pf
|`pfctl -s info` (parsed)
|`pf_states`, `pf_state_{searches,inserts,removals}_total`, `pf_counter_total{reason}`

|exec
|Subprocess, parses Influx line protocol
|`<measurement>_<field>{tags}` as gauges. Strings are skipped, bools become 0/1.

|internal
|Self
|`calipers_collector_duration_seconds{collector}` (histogram), `calipers_collector_errors_total{collector}`,
`calipers_build_info{version}`, own RSS/CPU

[[zfs-native]]
== ZFS without `zpool`

Telegraf runs `zpool list` every interval. calipers talks to the kernel the way `zpool` does:

* `/dev/zfs` ioctls on FreeBSD take a `zfs_iocparm_t` wrapping a pointer to `zfs_cmd_t`. The kernel
  copies `sizeof (zfs_cmd_t)` bytes in and out regardless of the size passed, so calipers hands it a
  zeroed 64 KiB buffer and only relies on the offsets of the fields it uses (`zc_name`,
  `zc_nvlist_dst{,_size}`, `zc_cookie`; checked at compile time). `vfs.zfs.version.ioctl` must be 15
  (`ZFS_IOCVER_OZFS`), otherwise the input refuses to start.
* Results are packed nvlists (native encoding), decoded by `src/nvlist.rs`.
* `POOL_CONFIGS` lists pools. Its generation cookie makes repeated calls return `EEXIST` until a pool
  is imported, exported or reconfigured, so the list is only re-read when it changed.
* `POOL_GET_PROPS` returns the exact numbers `zpool list` prints, keyed by property name, so no
  property enum numbers are hard-coded. `POOL_STATS` returns the vdev tree with `vdev_stat_t`
  (append-only array; indices for state, ops, bytes and errors are fixed) and `pool_scan_stat_t`.
* Neither ioctl needs privileges or writes to the pool history (`allow_log` is false).
* Health comes from `kstat.zfs.<pool>.misc.state`, computed by the kernel with the same
  `spa_state_to_name()` logic as `zpool list`. Vdev states use libzfs' `zpool_state_to_name()`
  mapping. One known difference: hot spares show as ONLINE where `zpool status` prints AVAIL.

Verified in the QEMU ZFS VM against `zpool list -Hp` and `zpool status` with a mirror, raidz1, cache
and spare pool, an offlined disk (DEGRADED propagation), injected corruption (385 checksum errors on
the right vdev) and a scrub.

[[memory-model]]
== Memory model

Linux and FreeBSD account for memory differently, and Telegraf (through gopsutil) reports FreeBSD
memory in a Linux-shaped way that is misleading on ZFS systems. calipers exports FreeBSD's own model.

[cols="1,2,2"]
|===
|FreeBSD |Meaning |Closest Linux concept

|active |Recently used pages |`Active`
|inactive |Not recently used; clean ones are reclaimed directly, dirty ones go to laundry |`Inactive`
|laundry |Dirty pages waiting to be written to swap or files before reuse |`Dirty` + anon pages headed for swap
|wired |Can't be paged out: kernel memory, ZFS ARC, UFS buffers, `mlock` |Slab + kernel stacks + `Mlocked` (+ page cache, for the ARC part)
|free |Immediately usable |`MemFree`
|ZFS ARC |Filesystem cache, *inside wired*; shrinks under pressure down to `c_min` |Page cache (`Cached`)
|===

Key differences:

* On Linux the filesystem cache is ordinary reclaimable page cache. On FreeBSD with ZFS it's the ARC,
  which is *wired* kernel memory. Telegraf's `used = total - (free + inactive + laundry)` therefore
  counts the whole ARC as used, and a healthy ZFS box looks permanently out of memory.
* `mem_available_bytes` = free + inactive + (ARC size - ARC `c_min`). Laundry is left out because
  reclaiming it needs swap I/O, the same reason Linux's `MemAvailable` leaves out anonymous memory.
  This is an estimate, like `MemAvailable`: some inactive pages are dirty, and some ARC is pinned.
* The real signal for memory pressure on FreeBSD is the page daemon: `free` dropping below
  `mem_free_target_bytes`, and `rate(mem_pagedaemon_scanned_pages_total[5m])` going up.

Useful queries:

[source,promql]
----
# Used, Linux-style (ARC counted as cache, not as used)
mem_managed_bytes - mem_available_bytes
# Stacked breakdown of all managed memory
mem_bytes
# Wired memory that isn't the ARC (kernel, mlock, UFS buffers)
mem_bytes{state="wired"} - ignoring(state) mem_zfs_arc_bytes
----

== Config

Our own format. It's close to Telegraf's so the translation is obvious, with typo detection through
`deny_unknown_fields`. The translated config lives in `resources/calipers.toml`. Excerpt:

[source,toml]
----
[agent]
interval = "10s"
# hostname = ""        # default: gethostname()
# omit_hostname = false

[global_tags]
realm = "hetzner"
role = "root.thaller.ws"

[exporter]
listen = "[::]:9273"

[inputs.cpu]
percpu = true
totalcpu = true

[inputs.disk]
ignore_fs = ["tmpfs", "devtmpfs"]

[inputs.smart]
interval = "60s"
excludes = ["/dev/ses0"]
nocheck = "standby"
path_smartctl = "/usr/local/sbin/smartctl"

[[inputs.procstat]]
exe = "nginx"
tag_with = ["pid"]

[[inputs.dns_query]]
domains = ["ip.thaller.ws"]
record_type = "A"
servers = ["1.0.0.1", "1.1.1.1", "8.8.4.4", "8.8.8.8"]
----

Dropped Telegraf agent options (they only matter for push outputs or don't apply): `flush_interval`,
`flush_jitter`, `metric_batch_size`, `metric_buffer_limit`, `precision`, `collection_jitter`,
`round_interval` (we always align to interval boundaries).

[[testing]]
== Testing and verification

. *Unit tests* for every parser and decoder: chrony float/packet decoding, DNS packet build/parse,
  Influx line protocol, `pfctl -s info`, `zpool list`, smartctl JSON (fixtures captured from real
  drives), devstat/xswdev struct layouts (`size_of` assertions against the C headers).
. *Cross-check*: `cargo clippy --target x86_64-unknown-freebsd` locally (no linker needed).
. *FreeBSD VM*: a FreeBSD 15.1 Firecracker microVM from
  https://github.com/acj/freebsd-firecracker[acj/freebsd-firecracker] (v0.12.0), see
  `resources/firecracker/`. `scripts/vm.sh start|stop|ssh|reset` manages it; binaries are
  cross-compiled on the host with `scripts/cross-build.sh` and copied over with scp. We compare our
  output against `sysctl`, `vmstat`, `iostat -x`, `swapinfo`, `netstat -i`, `pfctl -s info`, `ps`, and
  against Telegraf itself (installed from `pkg`) using the same config. The rootfs is UFS, so ZFS is
  tested in a second VM; pf and chrony come from base/pkg. Real SMART data is the only gap.
. *FreeBSD ZFS VM*: the Firecracker kernel is a custom build, and the stock `zfs.ko` panics it. ZFS is
  tested in a QEMU/KVM VM running the official `FreeBSD-15.1-RELEASE-amd64-BASIC-CLOUDINIT-zfs` image
  (GENERIC kernel, ZFS root), see `resources/qemu/vm.sh start|stop|ssh|scp|reset`. It needs no root:
  user-mode networking forwards SSH to `127.0.0.1:2222` and the metrics port to `127.0.0.1:9275`.
. *Resource check*: compare RSS and CPU time against Telegraf in the VM over 1 hour.
. *Final check on the server*: you run `calipers --once` and/or run it next to Telegraf on a different
  port. I won't touch the server myself.
